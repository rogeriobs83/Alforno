# Alforno Backend

Express API with MongoDB Atlas, configured for deployment on Render.

## Local setup

1. Copy `.env.example` to `.env` and provide real values.
2. Run `npm install`.
3. Initialize the Atlas collections and indexes with `mongosh "$MONGODB_URI" scripts/setup-mongodb.js`.
4. Run `npm run dev`.

## MongoDB Atlas

1. Create a database user and a cluster in Atlas.
2. Under **Network Access**, allow the address range required by the deployed service. Render services normally require `0.0.0.0/0` unless you use a static egress solution.
3. Copy the Atlas Node.js connection string into `MONGODB_URI`, replacing the username, password, and database name.
4. Use `alforno` as `MONGODB_DB` and run the initialization command above once.

## Render

The root [render.yaml](../render.yaml) creates the web service from `backend/`. Connect the repository in Render and create a Blueprint service. Set the following environment variables in Render:

- `MONGODB_URI`: Atlas connection string.
- `FRONTEND_ORIGIN`: final Vercel URL, such as `https://your-project.vercel.app`.
- `ADMIN_PASSWORD`: a strong administrator password.
- `UBER_EATS_CLIENT_SECRET` and `GETUKADDRESS_API_KEY`: only when those integrations are used.

`SESSION_SECRET` is generated by the Blueprint. Render supplies `PORT`; do not set a fixed production port. The service health endpoint is `/api/health`.
